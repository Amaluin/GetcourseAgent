# Анализ архитектуры RAG-системы GetcourseAgent с KAG (OpenSPG)

## Исполнительное резюме

В ходе анализа текущей RAG-системы GetcourseAgent была разработана комплексная архитектура на основе KAG (Knowledge Augmented Generation) от OpenSPG. Система трансформируется из классической RAG-архитектуры с Supabase и Neo4j в интеллектуальную платформу с графом знаний, логическим выводом и персонализированным обучением.

**Ключевое открытие**: В системе уже используются локальные модели Ollama (`nomic-embed-text`) и Groq (`llama-3.3-70b-versatile`), что позволяет создать гибридную архитектуру с минимальными затратами и максимальной производительностью.

## Текущее состояние системы

### Существующая архитектура
- **База данных**: Supabase + pgvector для векторного поиска
- **Графовая база**: Neo4j для хранения связей
- **Векторизация**: Эмбеддинги для семантического поиска
- **Парсинг**: Извлечение контента из уроков Getcourse
- **AI-интеграция**: Проверка домашних заданий с помощью LLM
- **Локальные модели**:
  - **Ollama**: `nomic-embed-text` для эмбеддингов
  - **Groq**: `llama-3.3-70b-versatile` как основная LLM
  - **Gemini**: `gemini-1.5-flash-latest` для анализа изображений

### Обнаруженные проблемы
1. **Ограниченная семантика**: Векторный поиск не учитывает сложные отношения
2. **Отсутствие вывода**: Нет логических правил для принятия решений
3. **Статическая персонализация**: Рекомендации основаны только на схожести
4. **Масштабируемость**: Трудности с горизонтальным масштабированием
5. **Контекстная ограниченность**: Недостаточно глубокий контекст для анализа

### Существующие преимущества
1. **Локальные модели**: Независимость от внешних API
2. **Стоимость эффективности**: Бесплатные эмбеддинги через Ollama
3. **Производительность**: Быстрые локальные вычисления
4. **Гибкость**: Возможность использования разных моделей для разных задач

## Предложенная архитектура KAG

### Компоненты системы

#### 1. SPG-Schema (Семантическая схема)
```
Образовательная доменная область:
├── Сущности
│   ├── Lesson (Урок)
│   ├── Assignment (Задание)
│   ├── Student (Студент)
│   ├── Submission (Работа)
│   ├── Concept (Концепция)
│   └── Resource (Ресурс)
└── Отношения
    ├── CONTAINS (Содержит)
    ├── STUDIES (Изучает)
    ├── SUBMITS (Выполняет)
    ├── EVALUATES (Оценивает)
    ├── REQUIRES (Требует)
    ├── USES (Использует)
    └── TEACHES (Обучает)
```

#### 2. OpenSPG Server (Ядро системы)
- **SPG-Builder**: Автоматическое извлечение знаний
- **SPG-Reasoner**: Логический вывод на основе правил
- **KNext Framework**: Программируемые компоненты
- **CloudExt**: Облачное масштабирование

#### 3. Гибридная модельная интеграция
- **Local Models Integration**: Интеграция с Ollama и Groq
- **HybridEmbeddingService**: Гибридные эмбеддинги (Ollama + OpenAI)
- **LocalSPGBuilder**: Извлечение концепций через Groq
- **LocalSPGReasoner**: Логический вывод через Groq

#### 4. Интегрированные компоненты
- **KAG Client**: TypeScript клиент для взаимодействия
- **Education Adapter**: Специализированный адаптер
- **Lesson Parser**: Интеграция с SPG-Builder
- **Reasoning Engine**: Выполнение логических правил

## Правила вывода (KGDSL)

### 1. StudentReadiness
```kgdsl
RULE StudentReadiness {
  DESCRIPTION "Check if student is ready to learn a concept"
  WHEN (
    student:Student -[MASTERED]-> prerequisite:Concept
    AND concept:Concept -[REQUIRES]-> prerequisite:Concept
  )
  INFER (
    student:Student -[READY_TO_LEARN]-> concept:Concept
  )
  CONFIDENCE 0.85
}
```

### 2. AssignmentDifficulty
```kgdsl
RULE AssignmentDifficulty {
  DESCRIPTION "Match assignment difficulty with student level"
  WHEN (
    student.level = 'intermediate'
    AND assignment.difficulty IN ['beginner', 'intermediate']
  )
  INFER (
    student:Student -[SUITABLE_FOR]-> assignment:Assignment
  )
  CONFIDENCE 0.8
}
```

### 3. LearningPath
```kgdsl
RULE LearningPath {
  DESCRIPTION "Generate optimal learning path"
  WHEN (
    target_concept:Concept -[REQUIRES*]-> intermediate_concept:Concept
    AND student:Student -[READY_TO_LEARN]-> intermediate_concept:Concept
  )
  INFER (
    student:Student -[NEXT_IN_PATH]-> intermediate_concept:Concept
  )
  CONFIDENCE 0.75
}
```

## KNext компоненты

### 1. LearningPathBuilder
- **Функциональность**: Построение образовательных путей
- **Вход**: ID студента, целевые концепции
- **Выход**: Оптимизированная последовательность уроков
- **Алгоритмы**: Графовые алгоритмы, оптимизация

### 2. PersonalizedRecommender
- **Функциональность**: Персонализированные рекомендации
- **Стратегии**: Content-based, collaborative, context-based
- **Фильтрация**: По времени, сложности, прогрессу
- **Объяснения**: Генерация причин рекомендаций

### 3. AdaptiveAssessment
- **Функциональность**: Адаптивная оценка знаний
- **Алгоритмы**: Item Response Theory, Bayesian inference
- **Персонализация**: Динамическая сложность
- **Обратная связь**: Детальный анализ результатов
