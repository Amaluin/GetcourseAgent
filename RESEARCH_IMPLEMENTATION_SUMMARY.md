## 🔍 Алгоритм работы скрипта

```
1. Инициализация браузера (browser.ts)
   └─ Загрузка существующей сессии или создание новой

2. Авторизация (auth.ts)
   └─ Вход в GetCourse
   └─ Сохранение сессии

3. Переход на GC_STREAM_URL
   └─ Ожидание загрузки страницы

4. Исследование текущей страницы
   ├─ researchCourses()
   │  ├─ Пробует различные селекторы
   │  ├─ Извлекает ID, название, описание, URL
   │  └─ Сохраняет HTML примеры
   │
   ├─ researchSections()
   │  ├─ Пробует различные селекторы
   │  ├─ Извлекает ID, название, порядок, URL
   │  └─ Сохраняет HTML примеры
   │
   ├─ researchLessons()
   │  ├─ Пробует различные селекторы
   │  ├─ Извлекает ID, название, порядок, URL
   │  └─ Сохраняет HTML примеры
   │
   └─ researchNavigation()
      ├─ Анализирует меню
      ├─ Анализирует breadcrumbs
      └─ Собирает примеры URL

5. Исследование альтернативных страниц (если мало данных)
   ├─ /teach/control
   ├─ /teach/control/stream
   ├─ /pl/teach/control/stream
   └─ /teach/control/my-courses

6. Углубленное исследование (если найдены курсы/разделы)
   ├─ Переход в первый курс → поиск разделов
   └─ Переход в первый раздел → поиск уроков

7. Сохранение результатов
   ├─ saveResultsToMarkdown()
   │  └─ Генерация research-results.md
   │
   └─ saveResultsToJson()
      └─ Генерация research-results.json

8. Закрытие браузера
   └─ Сохранение сессии
```

## 🔧 Технические особенности

### Используемые технологии
- **Playwright** - Браузерная автоматизация
- **TypeScript** - Типизация и безопасность
- **ts-node** - Выполнение TypeScript
- **Existing modules** - browser.ts, auth.ts для интеграции

### Стратегии поиска селекторов
1. **Прямой поиск** - Пробует стандартные селекторы
2. **Data-атрибуты** - Ищет data-course-id, data-section-id, etc.
3. **Частичное совпадение** - Использует `[class*="course"]`
4. **JavaScript анализ** - Анализирует DOM напрямую
5. **Альтернативные страницы** - Исследует различные URL
6. **Навигация по ссылкам** - Переходит по найденным ссылкам

### Обработка ошибок
- Таймауты для каждой операции (2-5 секунд)
- Try-catch блоки для устойчивости
- Продолжение работы при частичных неудачах
- Сохранение частичных результатов при ошибках

### Производительность
- Параллельная проверка селекторов
- Ранний выход при нахождении рабочих селекторов
- Оптимизированные таймауты
- Типичное время выполнения: 3-10 минут

## 🐛 Отладка и решение проблем

### Проблема: Не найдены элементы
**Решение:**
1. Запустите с `headless: false` в config.ts
2. Проверьте структуру страницы в DevTools
3. Обновите селекторы в скрипте
4. Повторите исследование

### Проблема: Таймауты при загрузке
**Решение:**
1. Увеличьте таймауты в скрипте
2. Проверьте скорость соединения
3. Используйте `waitUntil: 'domcontentloaded'`

### Проблема: Ошибки авторизации
**Решение:**
1. Проверьте .env файл
2. Удалите session.json
3. Попробуйте снова

### Проблема: Скрипт зависает
**Решение:**
1. Проверьте консольные логи
2. Запустите с видимым браузером
3. Проверьте наличие модальных окон
